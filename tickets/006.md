# 006 — Implement shared framebuffer processing and viewport geometry

Status: Implemented — remaining interactive checks tracked in docs/validation.md
Priority: P1
Depends on: 002, 003, 005

## Scope

Maintain a toolkit-independent canonical framebuffer and viewport geometry for both frontends. GPU upload and fullscreen integration belong to tickets 011 and 012.
- Handle negotiated pixel formats, rectangle updates, CopyRect if exposed, resize, and cursor updates according to the adapter contract.
- Validate dimensions and rectangle bounds before allocating or copying; define framebuffer limits and reject invalid updates without a panic.
- Publish explicitly owned, bounded framebuffer snapshots or a lossless update contract; never expose GTK/egui textures or graphics contexts in the core.
- Define shared fit-to-window and 1:1 geometry, aspect ratio and coordinate transforms; frontends apply logical/physical pixel scale and fullscreen changes.
- Distinguish local viewport scaling from requests to change the remote resolution; only offer the latter if verified.
- Record CPU/memory behavior and responsiveness on the actual target with a stated workload, without inventing performance targets.

## Acceptance criteria

- [ ] The actual Mac desktop renders correctly during updates, viewport changes, and fullscreen transitions.
- [ ] Focused tests cover pixel conversion, rectangle bounds, resize handling, and scaling transforms.
- [ ] Invalid/oversized updates cannot cause unchecked allocations or out-of-bounds access.
- [ ] Sustained session observation records resource use and any display limitations.

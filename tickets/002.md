# 002 — Evaluate embedded VNC libraries against the Mac mini

Status: Implemented — Apple login and Mac rendering confirmed; extended compatibility checks pending
Priority: P0
Depends on: 001

## Scope

Compare vnc-rs and LibVNCClient through Rust bindings, adding another candidate only with a reason.
- Inspect supported authentication/security types, encodings, resize/cursor/clipboard events, async or callback integration, cancellation, maintenance, and license obligations.
- Identify any FFI ownership/threading requirements for a C backend and scope unsafe code behind a small adapter.
- After implementation approval, use a disposable minimal probe to authenticate to the actual Mac mini, receive framebuffer updates, and send basic pointer/key input. Keep it outside the production UI.
- Record the actual macOS version and sharing configuration with the user. Do not assume macOS account authentication and a legacy VNC password are interchangeable.
- Verify negotiated transport protection and meet ticket 001 requirements. Document unsupported Apple extensions and any required Mac setup.
- Select a backend from evidence. If none works, report the gap and revise the plan before production integration.

## Acceptance criteria

- [ ] Candidate comparison records capabilities, versions, license implications, and selection rationale.
- [ ] An actual Mac connection proves authentication, framebuffer updates, and basic input; no credentials enter Git or logs.
- [ ] Transport properties and target setup are documented without unsupported claims.
- [ ] Backend adapter contract and any compatibility blockers are recorded.

## Implementation record

Implementation authorized by the user on 2026-10-18. See [validation results](../docs/validation.md) for completed checks and remaining work. The backend is LibVNCClient, selected to preserve the Mac’s Apple account authentication setup.

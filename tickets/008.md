# 008 — Apply Omarchy styling and desktop integration

Status: Implemented — remaining interactive checks tracked in docs/validation.md
Priority: P1
Depends on: 011, 012

## Scope

Give the graphical app a compact, keyboard-focused Omarchy appearance.
- Inspect installed theme palette/font conventions read-only and share neutral palette/font data and adapt it through egui styling and GTK CSS/settings with documented fallback behavior.
- Use compact connection rows, restrained borders, clear focus indicators, and accessible contrast. CLIamp informs interaction density; no terminal UI is involved.
- Verify dark/light palettes, missing/malformed palette fallback, and theme application on next launch. Live theme switching is optional.
- Add separately named egui and GTK desktop entries, a simple icon, and distinct window/application identities. Launch the selected graphical binary directly rather than through a terminal helper.
- Document optional Hyprland bindings using the installed configuration format; preserve existing bindings and avoid packaged Omarchy edits.
- Do not assume installation registers an `omarchy` CLI subcommand.

## Acceptance criteria

- [ ] Launcher discovery and launch work in the installed Omarchy session.
- [ ] Screens are usable with keyboard only and readable in one dark and one light theme.
- [ ] Theme failure falls back to a usable appearance; theme changes apply on next launch.
- [ ] Desktop identity/icon and documented optional binding behave consistently.

- [ ] Both frontends follow the same styling/shortcut intent, with documented toolkit-specific limitations.

Implementation authorized by the user on 2026-10-18. See [validation results](../docs/validation.md) for completed checks and remaining work. The backend is LibVNCClient, selected to preserve the Mac’s Apple account authentication setup.

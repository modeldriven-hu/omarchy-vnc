# 003 — Set up the Cargo workspace and UI-independent core

Status: Done — evidence in docs/validation.md
Priority: P1
Depends on: 002

## Scope

- Create separate core library, egui binary, and GTK4 binary packages as described in README.md.
- Keep all toolkit, window, GPU texture, and clipboard types outside the core. Neither frontend depends on the other.
- Put VNC adaptation, profile logic, session states, validated framebuffer data, and protocol input models in the core.
- Define plain Rust commands/events for authentication, state/error transitions, frames, resize, cursor, input, and disconnect. Redact secrets in diagnostics.
- Specify buffer ownership, bounded memory/backpressure, frame generations, and session identifiers. Coalescing must preserve rectangle updates, for example through a canonical framebuffer and latest snapshots.
- Run connection work independently of the UI event loops; provide toolkit-specific wakeups without polling continuously or blocking the main thread.
- Define cancellation, shutdown, and stale-event rejection; test these headlessly.
- Set independent workspace default members/build instructions, Rust version policy, locked dependencies, and frontend feature selection. No core features should enable a UI toolkit.

## Acceptance criteria

- [x] Core builds and tests without either UI toolkit or a display server.
- [x] Each frontend skeleton builds independently and opens on Wayland after implementation approval.
- [x] egui dependency/linkage inspection shows no GTK requirement; GTK builds do not enable egui rendering dependencies.
- [x] Slow consumers cannot cause unbounded frame queues, corrupt delta reconstruction, or freeze the UI.
- [x] Closing a UI cancels its owned connection and stale events cannot affect another session.

Implementation authorized by the user on 2026-10-18. See [validation results](../docs/validation.md) for completed checks and remaining work. The backend is LibVNCClient, selected to preserve the Mac’s Apple account authentication setup.

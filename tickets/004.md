# 004 — Implement shared profiles and connection presentation state

Status: Done — evidence in docs/validation.md
Priority: P1
Depends on: 003

## Scope

Implement UI-independent profile persistence and connection form validation. Frontend screens are implemented in tickets 011 and 012.
- Store non-secret profiles in the application XDG configuration directory, with a versioned data format and atomic saves.
- Support profile name, hostname/IP, explicit port (default 5900), display mode, clipboard preference, and optional default selection.
- Support add, edit, remove with confirmation, select, and connect; never invent the Mac address or auto-connect on startup.
- Validate duplicates, empty/invalid fields, malformed files, unsupported schema versions, and ports. Address support and limitations, including IPv6 if supported, must be explicit.
- Handle paths with spaces, restrictive permissions, write failures, and recovery without silently discarding existing profiles.

## Acceptance criteria

- [x] Keyboard navigation and profile CRUD work through shared core operations consumed by both frontends.
- [x] Named-profile startup selects the intended connection without embedding secrets.
- [x] Focused tests cover validation, corrupted files, atomic updates, and preservation on save failure.
- [x] Cancelling forms produces no unintended connection or file changes.

## Shared storage requirements

- Both binaries read and write the same versioned profiles and user preferences. Keep transient window state separate where needed.
- Prevent lost updates across simultaneous processes using locking or conflict detection around the full read-modify-write operation; atomic rename alone is insufficient.
- Test profile interoperability in both directions and conflicting edits, including deletion and default selection.

## Implementation record

Implementation authorized by the user on 2026-10-18. See [validation results](../docs/validation.md) for completed checks and remaining work. The backend is LibVNCClient, selected to preserve the Mac’s Apple account authentication setup.

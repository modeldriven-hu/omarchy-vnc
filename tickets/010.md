# 010 — Validate the complete Mac mini workflow and document release behavior

Status: In progress — automated checks passed; manual matrix pending
Priority: P1
Depends on: 009

## Scope

Verify the approved first release with meaningful automated and interactive checks.
- Check the headless core and each frontend independently, then the complete workspace. Run cargo fmt --check, cargo clippy with the agreed warning policy, cargo test, and a release build.
- Cover profile safety, session transitions/cancellation, framebuffer validation, input transforms, and any FFI ownership boundaries with focused tests.
- Smoke-test fresh setup, real Mac authentication, reconnect, framebuffer updates, keyboard/pointer, clipboard if enabled, scaling, fullscreen/local escape, and disconnect under Wayland in both frontends.
- Exercise wrong credentials, unreachable host, unsupported authentication, dropped connections, cancelled prompts, corrupt profiles, and window close during connection.
- Record tested versions and results, including locked/headless/multiple-monitor limitations where relevant. Do not mark checks requiring Mac access complete until performed.
- Write installation, Mac setup for the tested macOS version, usage, shortcut, transport/privacy, troubleshooting, and removal documentation.

## Acceptance criteria

- [ ] Automated checks and release build pass with commands recorded.
- [ ] Actual Omarchy-to-Mac-mini smoke-test results and tested versions are documented without secrets.
- [ ] Unsupported features and transport/authentication limitations are explicit.
- [ ] Documentation takes a new user from prerequisites through a saved working connection.

## Frontend parity validation

- Run the same Mac mini scenario matrix in egui and GTK; compare rendered updates, modifier handling, coordinate transforms, focus recovery, and clipboard consent behavior.
- Create/edit a profile in each frontend and open it in the other; exercise simultaneous modifications and confirm no silent data loss.
- Verify both can run with separate sessions and no credential/window-state leakage; do not promise remote-server simultaneous-session behavior until tested.
- Record GPU initialization failures and supported graphics environment for the OpenGL frontend.
- [ ] Core tests pass without a display; independent build checks and both interactive smoke-test records are complete.

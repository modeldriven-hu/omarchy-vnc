# 009 — Package reproducible builds and reversible user installation

Status: Done — evidence in docs/validation.md
Priority: P1
Depends on: 008

## Scope

Document a repeatable release build and user installation.
- List Cargo/build dependencies and runtime libraries for each frontend and the backend, including any native LibVNCClient requirement and license notices.
- Keep dependency installation explicit; do not silently perform privileged package changes.
- Provide installation into documented user paths for either or both binaries, their desktop entries, and icon, handling spaces and pre-existing unrelated files safely.
- Provide reinstall and uninstall behavior, preserving saved connections unless removal is explicitly requested.
- Include the lockfile and record build commands and supported environment; do not imply a binary is fully static when it needs native libraries.
- Defer AUR publication and external hosting to separate future work.

## Acceptance criteria

- [x] A clean build follows the documented prerequisites and locked dependencies.
- [x] Install/reinstall/uninstall affect only owned files and preserve profiles by default.
- [x] Runtime dependencies and licenses are documented accurately.
- [x] No system-wide or packaged Omarchy files are modified by the user installation.

## Independent builds and installation

- Document package-specific Cargo builds and installation for egui only, GTK only, and both.
- Verify egui/OpenGL builds in an environment without GTK development packages and inspect runtime linkage for unexpected GTK dependencies.
- Inspect optional dependency features (including dialogs, clipboard, and accessibility helpers) for unintended toolkit coupling.
- Uninstalling one frontend must preserve the other frontend, shared assets still in use, and shared profiles.
- [x] Independent build/install matrix passes, with native dependencies and results recorded for each frontend.

# 005 — Implement in-app authentication and connection lifecycle

Status: Implemented — remaining interactive checks tracked in docs/validation.md
Priority: P1
Depends on: 003, 004

## Scope

Implement the shared session controller and authentication command/event flow, with frontend dialogs in tickets 011 and 012.
- Prompt for the authentication inputs supported and validated in ticket 002; keep secrets transient and out of profiles, command arguments, diagnostics, and debug logs.
- Establish connections asynchronously with bounded timeouts and cancellable DNS/connect/authentication where supported. Document unavoidable backend constraints.
- Distinguish connecting, authentication failure, unsupported security type, unreachable host, connected, remote disconnect, and user disconnect.
- Mark the session connected only after protocol initialization succeeds.
- Provide explicit disconnect and manual reconnect; clear transient credentials and release resources when sessions end. Frontends supply secrets only through transient, redacted core messages.
- Prevent stale callbacks from updating a subsequent connection.

## Acceptance criteria

- [ ] Real Mac authentication succeeds and failures return useful, non-secret errors.
- [ ] Cancel, disconnect, reconnect, and window close leave no owned tasks/connections running.
- [ ] State-machine checks cover timeout, rejected authentication, remote disconnect, and stale events.
- [ ] A failed connection leaves the UI responsive with a clear next action.

## Implementation record

Implementation authorized by the user on 2026-10-18. See [validation results](../docs/validation.md) for completed checks and remaining work. The backend is LibVNCClient, selected to preserve the Mac’s Apple account authentication setup.
